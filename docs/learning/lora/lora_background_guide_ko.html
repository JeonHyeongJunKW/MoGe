Linear layer · 선형층의 약속

y = W₀x + b

x는 입력 특징, W₀는 기존 가중치, b는 bias(편향), y는 출력이다. 입력 차원이 n, 출력 차원이 m이면 W₀는 m×n이다. 이 자료는 x를 열벡터로 표기한다.

코드에서 전치가 보이는 이유

PyTorch는 배치 입력을 행 단위로 저장하므로 Linear는 XW₀ᵀ+b로 계산한다. 수학 표기와 배열 배치 방식이 달라 보일 뿐 같은 연산이다. [4]

PEFT · 적은 파라미터만 학습하는 방법

Parameter-Efficient Fine-Tuning은 학습하는 파라미터를 줄이는 방법들의 범주다. LoRA는 그중 하나다. 모델의 모든 가중치를 직접 수정하는 full fine-tuning과 구분한다. [2]

02 / CORE IDEA

기존 출력에 작은 보정을 더한다

LoRA는 원래 가중치 W₀를 고정하고, 그 변화량 ΔW를 두 작은 행렬의 곱으로 표현한다. [1]

y = W₀x + b + sB(Ax)　　s = α / r

회색: 고정된 원래 경로 / 초록: 학습하는 보정 경로. 그림에서는 bias를 생략했다.

기호크기역할
W₀m×n기존 변환
Ar×n입력을 r개 중간 성분으로 변환
Bm×r중간 성분을 출력 공간으로 변환
s = α/r스칼라보정 출력에 곱하는 배율
Low rank · 변화량의 표현 범위를 제한

ΔW=sBA의 rank는 최대 r이다. W₀ 자체가 저랭크일 필요는 없다. A와 B는 보통 학습으로 찾으며, 매 단계마다 원래 W₀를 SVD로 분해하는 방식은 아니다. [1]

03 / WORKED EXAMPLE

작은 숫자로 직접 계산해 보기

입력 2차원, 출력 2차원, rank 1, s=1인 학습용 예제다. bias는 0으로 둔다.

기존 가중치
W₀ = [1  0]
     [0  1]
보정 행렬
A = [1  2]
B = [0.1]
    [0.2]
입력
x = [3]
    [4]

1. 원래 출력

W₀x = [3, 4]ᵀ

2. 작은 보정 경로

Ax = 1×3 + 2×4 = 11
B(Ax) = [1.1, 2.2]ᵀ

3. 두 결과를 합치기

y = [3, 4]ᵀ + [1.1, 2.2]ᵀ = [4.1, 6.2]ᵀ

이때 BA=[[0.1, 0.2], [0.2, 0.4]]다. 두 번째 행은 첫 번째 행의 2배이므로 서로 독립적인 행 방향은 하나다. 이것이 rank 1의 한 예다.

파라미터 절감은 큰 행렬에서 확인한다

이 2×2 예제는 W가 4개, A+B도 4개라 절감이 없다. 384×384 행렬과 rank 4라면 기존 147,456개 대신 4×384+384×4=3,072개를 학습한다. 해당 행렬 기준 약 2.08%다. bias는 제외한 계산이다.

왜 A와 B를 모두 0으로 두지 않을까?

g=∂L/∂y라 두면, 한 입력에 대한 보정 경로의 기울기는 아래와 같다. 현재 예제에서는 가중치 감쇠 같은 optimizer의 추가 효과를 제외한다.

∂L/∂B = s · g(Ax)ᵀ
∂L/∂A = s · Bᵀg xᵀ

A와 B가 모두 0이면 두 기울기가 모두 0이 되어 보정 경로가 학습을 시작하지 못한다. A는 난수, B는 0이면 첫 단계에서 B가 먼저 바뀔 수 있고, 이후 A에도 손실 기울기가 흐른다.

Frozen과 no_grad는 다르다

가중치를 고정해도 앞쪽의 학습 파라미터까지 기울기를 전달해야 하면 연산 그래프가 필요하다. LoRA가 들어간 전체 Student backbone을 torch.no_grad()로 감싸면 adapter 학습도 끊긴다. Teacher의 오프라인 추론에는 기울기 기록이 필요 없다. [5]

현재 코드에서 확인할 항목

기존 encoder 파라미터는 고정, lora_A와 lora_B는 학습 가능이어야 한다. Neck·heads도 별도로 학습한다. 저장 후 고정 가중치 불변, adapter 변화, NaN/Inf 유무를 확인한다. [P1,P2]

05 / HYPERPARAMETERS

rank·alpha·학습률은 역할이 다르다

설정을 바꿀 때는 “표현 가능한 변화”와 “업데이트 크기”를 나누어 생각한다.

설정무엇을 바꾸나현재 후보
Rank r · 중간 차원ΔW의 최대 rank와 adapter 파라미터 수4 / 8
Alpha α · 스케일 설정보정 출력 배율 s=α/r8 / 16 → 둘 다 s=2
Learning rate · 학습률optimizer가 A·B를 갱신하는 크기1e-5
Target modules · 적용 층어느 가중치에 LoRA를 붙일지마지막 4블록 qkv·proj
Dropout · 임의 누락학습 중 보정 경로 입력 등을 일부 제거현재 미사용

Rank가 두 배면 성능도 두 배일까?

학습할 수 있는 변화의 범위는 넓어지지만, 실제 품질은 데이터·학습률·적용 위치에 달려 있다. Rank 8이 rank 4보다 낫다는 결론은 평가 후에만 내린다. [2]

α/r를 같게 하면 무엇이 통제될까?

현재 r=4, α=8과 r=8, α=16은 출력 배율을 2로 맞춘다. 다만 A·B의 크기와 최적화 경로가 달라 두 조건의 실제 업데이트 크기까지 같아지는 것은 아니다.

이번 sweep을 읽는 방법

Rank 4와 8은 같은 LoRA 학습률로 비교한다. 일반 학습의 backbone LR은 5e-7이고 LoRA는 1e-5다. 따라서 일반 학습과의 비교는 두 학습 설정의 실용적 비교이며, 동일 학습률에서 LoRA 효과만 분리한 실험은 아니다. [P2]

Q·K·V는 무엇인가?

Query(조회 벡터)와 Key(비교 벡터)로 어떤 위치의 정보를 참고할지 계산하고, Value(전달할 특징)를 섞는다. proj는 섞인 결과를 다음 특징 공간으로 바꾸는 선형층이다. 여기서는 Q·K·V가 하나의 qkv 행렬에 합쳐져 있어 세 부분 전체를 보정한다.

Rank 4 adapter는 총 몇 개의 숫자를 학습할까?

현재 Small backbone의 특징 차원 d=384를 사용하면 qkv는 1152×384, proj는 384×384이다.

블록당: r(384+1152) + r(384+384) = 2304r
4블록: 9216r → r=4: 36,864 / r=8: 73,728
모든 학습 파라미터가 adapter는 아니다

위 계산은 LoRA 부분만 센 값이다. 이번 실험은 neck·heads도 학습하므로 전체 학습 파라미터는 약 1,279만 개 또는 1,283만 개다.

Knowledge distillation · 지식 증류

큰 모델의 예측을 학습 신호로 사용해 다른 모델에 능력을 옮기는 발상이다. [6] 현재 코드는 분류 확률의 temperature나 KL loss를 사용하는 방식이 아니라, 미리 저장한 metric depth(실제 거리 단위 깊이)를 이용하는 오프라인 pseudo-label 학습이다. [P4]

현재 데이터와 손실

CARLA의 GT(기준 정답)를 75%, 실제 Teacher pseudo를 25% 확률로 샘플링한다. Pseudo 쪽 손실 항의 기존 가중치에는 0.25를 추가로 곱한다. 이 두 비율은 서로 다른 설정이다. [P2]

개념적 기대 손실 ≈ 0.75 E[LCARLA]
+ 0.25 × 0.25 E[Lpseudo]

이 식은 샘플링과 가중치 관계를 설명한다. 실제 손실은 여러 기하·스케일 항으로 구성되며, 기울기 기여 비율이 위 계수와 같다는 뜻은 아니다.

Teacher가 좋아 보였다는 관찰의 활용

실제 영상에 적응시킬 근거가 되지만 Teacher 예측도 오차를 포함한다. 현재 pseudo에는 normal·mask 직접 지도 손실을 제외하고, 유효한 깊이 픽셀을 사용한다. 별도 촬영 세션에서 개선을 확인해야 한다. [P2,P4]

공통 조건

Student는 best_flip_mild_t400_total18500.pt, 입력 400 tokens(특징 토큰), 3,000회 업데이트, 유효 배치 32다. 데이터·증강·seed·CARLA 평가 조건을 맞추며 neck·heads 학습은 모두 유지한다. [P2]

무엇이 개선됐는지 나누어 평가

Teacher와 더 비슷해졌다는 사실만으로 실제 거리 정확도가 좋아졌다고 판단할 수는 없다.

확인할 질문평가 방법
기존 CARLA 성능이 유지되는가?고정 validation의 REL↓, δ1↑ 비교
실제 장면의 형태가 좋아졌는가?별도 촬영 세션에서 같은 장면을 나란히 비교
실제 거리 단위가 맞는가?거리 기준이 있는 장면이나 독립 GT에서 오차 확인
장면 간 일관성이 있는가?카메라·거리·조명·얇은 구조별로 나눠 확인

지표의 뜻

REL = mean( |d̂ − d| / d )
δ1 = mean( max(d̂/d, d/d̂) < 1.25 )

d는 유효한 기준 깊이, d̂는 예측 깊이다. 예를 들어 실제 2m를 2.2m로 예측하면 해당 픽셀의 상대 오차는 0.1이다. 평가 mask·범위·정렬 방식은 모든 조건에서 같아야 한다.

학습이 끝나면 병합해서 사용

선형 보정이므로 W*=W₀+sBA로 합치면 일반 Linear와 같은 구조로 추론할 수 있다. [1,3]

W* = W₀ + (α/r)BA
W*x + b = W₀x + b + (α/r)B(Ax)

병합 전과 후

상태저장 내용·특징
현재 LoRA 체크포인트기본 가중치 + A·B + 학습된 neck·heads + 설정
일반 모델로 병합변경된 W* + 학습된 neck·heads, 별도 adapter 없음

일반적인 adapter-only 저장은 작지만 정확히 같은 base 모델이 따로 필요하다. 현재 코드는 완전한 모델 파일을 저장하므로 “LoRA 체크포인트는 항상 작다”는 설명이 적용되지 않는다. [3,P1]

python tools/merge_moge2_lora.py \
  --checkpoint workspace/v4l2_lora_sweep/RUN/lora_r4/checkpoint/best.pt \
  --output pretrained/student400_v4l2_lora_r4_merged.pt

RUN은 실제 생성된 실행 폴더명으로 바꾼다. 출력 파일은 새 이름을 사용한다.

실행 후 확인할 것

같은 RGB와 같은 전처리로 병합 전후의 points·normal·mask·metric scale을 비교한다. 부동소수점 연산 순서 때문에 미세한 차이는 있을 수 있다. 최종 배포 환경에서도 입력 크기·토큰 수·거리 단위를 확인한다.

이번 구현에서 확인한 범위

Rank 4 동작 확인 체크포인트를 병합하고 FP32 출력의 수치 일치를 확인했다. 이는 구현 검증이며 깊이 성능 개선의 증거는 아니다. 별도 저장한 merged 파일에는 optimizer 재개 상태가 없다. [P1,P3]

12 / SELF CHECK

다섯 문제로 이해 확인하기

답을 보기 전에 각 질문을 한두 문장으로 설명해 본다.

01

Rank 8이면 원래 W₀도 rank 8일까?

어느 행렬의 rank에 제한이 걸리는지 적어 보자.

02

왜 A와 B를 모두 0으로 초기화하지 않을까?

5쪽의 두 미분 식에 A=0, B=0을 대입해 보자.

03

512×512 층에 rank 8을 붙이면?

기존 행렬과 A+B의 파라미터 수, 학습 비율을 구하자. Bias는 제외한다.

04

Teacher가 고정이면 Student도 학습이 안 될까?

학습 목표를 생성하는 모델과 gradient를 받는 모델을 구분해 보자.

05

LoRA rank 8의 train loss만 더 낮다면?

어떤 평가가 있어야 더 나은 모델이라고 말할 수 있을까?

짧은 답

01 ΔW=sBA의 rank가 최대 8이다. W₀의 rank 제한은 없다.
02 두 손실 기울기가 모두 0이 되기 때문이다.
03 262,144개 대 8,192개, 비율 3.125%.
04 고정 Teacher가 목표를 제공하고 Student의 A·B 및 neck·heads는 갱신된다.
05 독립 실제 세션의 품질·거리 오차, CARLA 성능 유지와 자원 비용을 비교해야 한다.
